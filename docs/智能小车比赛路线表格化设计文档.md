# 智能小车比赛路线表格化设计文档

> 状态：已实现（基于当前代码 2026-06-14）
> 实现文件：`User_Application/userapp_race_table.c/h` + `User_Application/userapp_race.c/h`

## 1. 背景与现状

当前工程已完成从阻塞式 MCM 到非阻塞 MCM 的迁移。路线调度已采用表格驱动方式：

- **路线表**：静态数组描述"做什么"
- **调度器** `userapp_race_table.c`：逐行解释动作表，启动 MCM 动作，等待完成，跳转
- **路线管理** `userapp_race.c`：启动请求接收、周期推进

## 2. 设计目标 ✅ 已实现

用户填写动作表即可定义比赛路线，无需手写状态机：

```c
static const USER_Race_Action_t race_template_actions[] = {
    {USER_Race_ACTION_MOVE_DISTANCE, 500.0f, 300.0f, 3000u, 1, 0u},
    {USER_Race_ACTION_ROTATE_ANGLE,  180.0f,  90.0f, 2500u, 2, 0u},
    {USER_Race_ACTION_MOVE_DISTANCE, 500.0f, 300.0f, 3000u, 3, 0u},
    {USER_Race_ACTION_ROTATE_ANGLE,  180.0f,  90.0f, 2500u, 4, 0u},
    {USER_Race_ACTION_END,             0.0f,   0.0f,    0u, -1, 0u},
};
```

## 3. 分层原则 ✅ 已实现

### 3.1 路线表只描述"做什么"

路线表不关心速度 PID、编码器更新、IMU 融合、动作内部状态。

只描述：前进距离、旋转角度、等待时间、是否停止、完成后跳转。

### 3.2 MCM 层负责"怎么做"

MCM（`userapp_mcm.c`）负责真正的运动执行：
- 非阻塞直行/后退（梯形速度规划 + 航向保持 + 距离反馈）
- 非阻塞原地旋转（梯形角速度规划 + 角度反馈）
- 停止、超时、错误处理

路线调度器不直接控制电机，只通过 `USER_MCM_Start*()` / `USER_MCM_IsBusy()` / `USER_MCM_GetStatus()` 消费 MCM。

### 3.3 调度器负责"按表执行"

动作表调度器（`userapp_race_table.c`）负责：
1. 从动作表读取当前行
2. 调用对应 MCM 启动接口
3. 周期性检查 MCM 是否完成
4. 完成后按 `next_index` 跳转
5. 失败时进入错误状态
6. 遇到 `USER_Race_ACTION_END` 路线结束

## 5. 动作类型定义 ✅ 已实现

```c
typedef enum {
    USER_Race_ACTION_NONE = 0,
    USER_Race_ACTION_MOVE_DISTANCE,   // 直行指定距离 (param1=mm, param2=mm/s)
    USER_Race_ACTION_ROTATE_ANGLE,    // 旋转指定角度 (param1=deg, param2=deg/s)
    USER_Race_ACTION_WAIT_MS,         // 等待指定毫秒 (param1=ms)
    USER_Race_ACTION_STOP,            // 停止电机
    USER_Race_ACTION_END              // 路线结束
} USER_Race_ActionType_t;
```

## 6. 动作表结构体 ✅ 已实现

```c
typedef struct {
    USER_Race_ActionType_t action_type;  // 动作类型
    float param1;                        // 主参数：距离mm / 角度deg / 等待时间ms
    float param2;                        // 次参数：最大速度mm/s / 最大角速度deg/s
    uint32_t timeout_ms;                 // 表层超时（0=不启用）
    int16_t next_index;                  // 成功后跳转行索引（-1=路线结束）
    uint16_t flags;                      // 预留扩展
} USER_Race_Action_t;
```

## 9. 公开 API ✅ 已实现

| 函数 | 说明 |
|------|------|
| `USER_Race_TableExecutor_Init()` | 初始化/复位执行器 |
| `USER_Race_TableExecutor_Start()` | 启动路线执行（从第 0 行开始） |
| `USER_Race_TableExecutor_Update()` | 每 10ms 推进（核心状态机） |
| `USER_Race_TableExecutor_Stop()` | 停止执行 |
| `USER_Race_TableExecutor_IsBusy()` | 是否正在执行 |
| `USER_Race_TableExecutor_IsDone()` | 是否已完成/出错 |

## 10. 调度器核心逻辑 ✅ 已实现

```c
void USER_Race_TableExecutor_Update(executor) {
    // 步骤1：校验当前索引
    // 步骤2：遇到 END → DONE
    // 步骤3：首次启动 → 调用 USER_Race_StartAction()
    //        - MOVE_DISTANCE → USER_MCM_StartStraight()
    //        - ROTATE_ANGLE  → USER_MCM_StartSpin()
    //        - WAIT_MS       → 只计时
    //        - STOP          → USER_MCM_Cancel()
    // 步骤4：超时检查 → ERROR
    // 步骤5：MCM 完成？→ 检查状态
    // 步骤6：成功 → next_index 跳转 / -1 → DONE
    // 步骤7：失败 → ERROR
}
```

## 11. 路线启动流程 ✅ 已实现

1. UI 路线页面（PAGE_TEMPLATE）ENTER 长按
2. 充电进度条 2s（`USER_UI_Route_StartCharge`）
3. 倒计时 1s（`USER_UI_ROUTE_COUNTDOWN_MS`）
4. `USER_Race_RequestStart(RACE_ROUTE_TEMPLATE)`
5. `USER_Race_Task()` 检测到请求 → `USER_Race_TableExecutor_Start()`
6. 后续每个 10ms 周期 → `USER_Race_TableExecutor_Update()` 推进
7. 路线结束/出错 → 自动复位执行器
