# 智能小车比赛路线表格化设计文档

## 1. 背景

当前工程已经完成以下基础验证：

1. 实车底层闭环确认；
2. `main.c` 中 10ms 固定速度目标为 0 的逻辑已经修正或隔离；
3. 阻塞式 MCM 基础动作已经验证，例如 `MoveDistance(500, 300)` 和 `RotateAngle(180, 90)`。

下一阶段目标是将比赛路线从大量 `switch-case` 步骤代码，改造成**表格驱动的线性动作调度系统**。

核心思想：

> 比赛路线由一张动作表描述，每一行代表一个动作；状态机只负责读取当前行、启动动作、等待动作完成、跳转到下一行。

这样用户只需要填写动作表，不需要为每条路线手写复杂状态机。

---

## 2. 设计目标

### 2.1 用户侧目标

用户希望以后编写比赛路线时，只需要填写类似下面这样的动作表：

```c
static const USER_RACE_Action_t race_template_actions[] =
{
    // 动作类型, 距离/角度/时间, 速度/角速度, 超时, 下一步, 标志位
    {USER_RACE_ACTION_MOVE_DISTANCE, 500.0f, 300.0f, 3000, 1, 0},
    {USER_RACE_ACTION_ROTATE_ANGLE,  180.0f,  90.0f, 2500, 2, 0},
    {USER_RACE_ACTION_MOVE_DISTANCE, 500.0f, 300.0f, 3000, 3, 0},
    {USER_RACE_ACTION_ROTATE_ANGLE,  180.0f,  90.0f, 2500, 4, 0},
    {USER_RACE_ACTION_END,             0.0f,   0.0f,    0, -1, 0},
};
```

而不是手写大量类似这样的状态代码：

```c
switch (race_step)
{
    case STEP_FORWARD_1:
        ...
        break;

    case STEP_WAIT_FORWARD_1:
        ...
        break;

    case STEP_ROTATE_1:
        ...
        break;

    case STEP_WAIT_ROTATE_1:
        ...
        break;
}
```

---

## 3. 分层原则

### 3.1 路线表只描述“做什么”

路线表不应该关心：

- 速度 PID 如何计算；
- 编码器如何更新；
- IMU 如何参与角度闭环；
- 动作是否处于加速、匀速、减速阶段；
- 具体运动动作内部状态。

路线表只描述：

- 前进多少距离；
- 旋转多少角度；
- 等待多长时间；
- 是否停止；
- 当前动作完成后进入哪一步。

---

### 3.2 MCM 层负责“怎么做”

MCM，即 Motion Control Manager，负责真正执行动作，例如：

- 非阻塞直行；
- 非阻塞旋转；
- 后续可扩展圆弧运动；
- 停止；
- 刹车；
- 动作超时；
- 动作失败；
- 传感器异常处理。

路线调度器不直接控制电机，只调用 MCM 的非阻塞接口。

---

### 3.3 调度器负责“按表执行”

动作表调度器负责：

1. 从动作表读取当前动作；
2. 判断当前动作是否已经启动；
3. 如果未启动，则调用对应的 MCM 启动接口；
4. 周期性检查 MCM 动作是否完成；
5. 如果完成，根据动作表中的 `next_index` 进入下一步；
6. 如果失败，进入错误状态；
7. 如果遇到 `USER_RACE_ACTION_END`，则路线执行完成。

## 6. 动作表结构体设计

建议定义：

```c
typedef struct
{
    USER_RACE_ActionType_t action_type;

    // 主参数：
    // MOVE_DISTANCE : 距离，单位 mm
    // ROTATE_ANGLE  : 角度，单位 deg
    // WAIT_MS       : 等待时间，单位 ms
    float param1;

    // 次参数：
    // MOVE_DISTANCE : 最大速度，单位 mm/s
    // ROTATE_ANGLE  : 最大角速度，单位 deg/s
    // WAIT_MS       : 填 0
    float param2;

    // 当前动作最大允许执行时间，单位 ms
    // 如果填 0，表示使用动作内部默认超时
    uint32_t timeout_ms;

    // 当前动作完成后的下一行动作索引
    // >= 0：跳转到指定动作行
    // -1 ：路线结束
    int16_t next_index;

    // 标志位，暂时可以填 0，后续扩展用
    uint16_t flags;
} USER_RACE_Action_t;
```

## 8. 调度器运行上下文

建议定义：

```c
typedef struct
{
    const USER_RACE_Action_t *table;
    uint16_t table_size;

    int16_t current_index;
    bool action_started;

    USER_RACE_TableState_t state;
    USER_RACE_TableResult_t result;

    uint32_t action_elapsed_ms;
    uint32_t scheduler_period_ms;
} USER_RACE_TableExecutor_t;
```

说明：

| 字段 | 含义 |
|---|---|
| `table` | 当前路线动作表指针 |
| `table_size` | 当前动作表行数 |
| `current_index` | 当前正在执行的动作行 |
| `action_started` | 当前动作是否已经启动 |
| `state` | 调度器状态 |
| `result` | 调度器执行结果 |
| `action_elapsed_ms` | 当前动作已经执行的时间 |
| `scheduler_period_ms` | 调度器调用周期，例如 10ms 或 20ms |

## 11. 调度器核心逻辑伪代码

```c
void USER_RACE_TableExecutor_Update(USER_RACE_TableExecutor_t *executor)
{
    if (executor == NULL)
    {
        return;
    }

    if (executor->state != USER_RACE_TABLE_STATE_RUNNING &&
        executor->state != USER_RACE_TABLE_STATE_WAIT_ACTION_DONE)
    {
        return;
    }

    if (executor->current_index < 0 ||
        executor->current_index >= executor->table_size)
    {
        executor->state = USER_RACE_TABLE_STATE_ERROR;
        executor->result = USER_RACE_TABLE_RESULT_INVALID_INDEX;
        USER_MCM_Stop();
        return;
    }

    const USER_RACE_Action_t *action = &executor->table[executor->current_index];

    if (action->action_type == USER_RACE_ACTION_END)
    {
        executor->state = USER_RACE_TABLE_STATE_DONE;
        executor->result = USER_RACE_TABLE_RESULT_OK;
        USER_MCM_Stop();
        return;
    }

    if (!executor->action_started)
    {
        bool started = USER_RACE_StartAction(action);

        if (!started)
        {
            executor->state = USER_RACE_TABLE_STATE_ERROR;
            executor->result = USER_RACE_TABLE_RESULT_INVALID_ACTION;
            USER_MCM_Stop();
            return;
        }

        executor->action_started = true;
        executor->action_elapsed_ms = 0;
        executor->state = USER_RACE_TABLE_STATE_WAIT_ACTION_DONE;
    }

    executor->action_elapsed_ms += executor->scheduler_period_ms;

    if (action->timeout_ms > 0 && executor->action_elapsed_ms > action->timeout_ms)
    {
        executor->state = USER_RACE_TABLE_STATE_ERROR;
        executor->result = USER_RACE_TABLE_RESULT_TIMEOUT;
        USER_MCM_Stop();
        return;
    }

    if (USER_RACE_IsActionDone(action))
    {
        if (!USER_RACE_IsActionSuccess(action))
        {
            executor->state = USER_RACE_TABLE_STATE_ERROR;
            executor->result = USER_RACE_TABLE_RESULT_ACTION_FAILED;
            USER_MCM_Stop();
            return;
        }

        executor->action_started = false;

        if (action->next_index < 0)
        {
            executor->state = USER_RACE_TABLE_STATE_DONE;
            executor->result = USER_RACE_TABLE_RESULT_OK;
            USER_MCM_Stop();
            return;
        }

        executor->current_index = action->next_index;
        executor->state = USER_RACE_TABLE_STATE_RUNNING;
    }
}
```

## 12. 启动动作函数设计

建议内部实现一个静态函数：

```c
static bool USER_RACE_StartAction(const USER_RACE_Action_t *action)
{
    if (action == NULL)
    {
        return false;
    }

    switch (action->action_type)
    {
        case USER_RACE_ACTION_MOVE_DISTANCE:
            return USER_MCM_StartMoveDistance(action->param1,
                                              action->param2,
                                              action->timeout_ms);

        case USER_RACE_ACTION_ROTATE_ANGLE:
            return USER_MCM_StartRotateAngle(action->param1,
                                             action->param2,
                                             action->timeout_ms);

        case USER_RACE_ACTION_WAIT_MS:
            // WAIT 动作不需要启动 MCM
            return true;

        case USER_RACE_ACTION_STOP:
            USER_MCM_Stop();
            return true;

        case USER_RACE_ACTION_END:
            return true;

        default:
            return false;
    }
}
```

## 13. 判断动作完成函数设计

```c
static bool USER_RACE_IsActionDone(const USER_RACE_Action_t *action)
{
    if (action == NULL)
    {
        return true;
    }

    switch (action->action_type)
    {
        case USER_RACE_ACTION_MOVE_DISTANCE:
        case USER_RACE_ACTION_ROTATE_ANGLE:
            return USER_MCM_IsFinished();

        case USER_RACE_ACTION_WAIT_MS:
            // WAIT_MS 的完成判断由 executor->action_elapsed_ms >= param1 处理
            // 这个函数可以结合 executor 实现，或者单独在 Update 中判断
            return false;

        case USER_RACE_ACTION_STOP:
        case USER_RACE_ACTION_END:
            return true;

        default:
            return true;
    }
}
```

注意：`WAIT_MS` 动作需要用 `executor->action_elapsed_ms` 和 `action->param1` 判断完成，所以实际实现中可以把该函数设计成：

```c
static bool USER_RACE_IsActionDone(USER_RACE_TableExecutor_t *executor,
                                   const USER_RACE_Action_t *action)
{
    ...
}
```

然后在内部判断：

```c
case USER_RACE_ACTION_WAIT_MS:
    return executor->action_elapsed_ms >= (uint32_t)action->param1;
```

## 14. 判断动作成功函数设计

```c
static bool USER_RACE_IsActionSuccess(const USER_RACE_Action_t *action)
{
    if (action == NULL)
    {
        return false;
    }

    switch (action->action_type)
    {
        case USER_RACE_ACTION_MOVE_DISTANCE:
        case USER_RACE_ACTION_ROTATE_ANGLE:
            return USER_MCM_GetResult() == USER_MCM_RESULT_OK;

        case USER_RACE_ACTION_WAIT_MS:
        case USER_RACE_ACTION_STOP:
        case USER_RACE_ACTION_END:
            return true;

        default:
            return false;
    }
}
```

## 18. 与主循环的集成方式

建议在 `main.c` 的 10ms 或 20ms 周期任务中调用。

如果 MCM 的控制周期是 10ms，推荐：

```c
if (USER_SYSTEM_ConsumeTime(&system_time.t_10ms))
{
    USER_STATE_Update10ms();

    USER_MCM_Update10ms();

    USER_RACE_TableExecutor_Update(&race_executor);

    USER_MotorSpeedLoop_Update10ms();
}
```

或者如果已有电机速度闭环在 MCM 内部处理，则不要重复调用。

关键原则：

> `speed_pid[].target` 的写入权应该集中在 MCM 或运动控制层，不要在 `main.c`、路线层、显示层到处写。

## 20. 错误处理建议

调度器遇到以下情况应该进入 `ERROR`：

| 错误 | 处理 |
|---|---|
| 当前索引越界 | 停止 MCM，结果设为 `INVALID_INDEX` |
| 动作类型非法 | 停止 MCM，结果设为 `INVALID_ACTION` |
| 动作超时 | 停止 MCM，结果设为 `TIMEOUT` |
| MCM 动作失败 | 停止 MCM，结果设为 `ACTION_FAILED` |
| 用户中止 | 停止 MCM，结果设为 `ABORTED` |

错误状态下应停止电机：

```c
USER_MCM_Stop();
```

并且可以在 OLED Debug 页面显示：

- 当前路线状态；
- 当前动作行号；
- 当前错误码；
- 当前 MCM 结果。

### 23.6 加入主循环周期调用

在 10ms 或 20ms 周期中调用：

```c
USER_RACE_TableExecutor_Update(&race_executor);
```

推荐 10ms，与 MCM 控制周期一致。

## 24. 初版验收标准

实现完成后，至少满足：

1. 可以通过动作表执行当前模板路径；
2. OLED、LiDAR、按键、Modbus 等周期任务不再被阻塞；
3. 动作失败或超时时能够停止电机；
4. 动作表执行完成后进入 DONE 状态；
5. 当前动作行号可以用于 OLED 调试显示；
6. 后续新增路线只需要增加新的动作表，不需要写新的路线状态机。

## 25. 设计总结

本设计的核心价值是：

> 将“路线逻辑”从代码流程中抽离出来，变成一张可维护的动作表。

最终目标是让用户只关心这个表怎么填：

```c
static const USER_RACE_Action_t my_race_actions[] =
{
    {USER_RACE_ACTION_MOVE_DISTANCE, 800.0f, 350.0f, 4000, 1, 0},
    {USER_RACE_ACTION_ROTATE_ANGLE,   90.0f,  80.0f, 2500, 2, 0},
    {USER_RACE_ACTION_MOVE_DISTANCE, 300.0f, 250.0f, 3000, 3, 0},
    {USER_RACE_ACTION_END,             0.0f,   0.0f,    0, -1, 0},
};
```

而状态机、动作启动、等待完成、错误处理、下一步跳转全部由通用调度器负责。
